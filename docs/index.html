Design the operator panel in a browser. Run it on the machine.

HMI Studio is an open-source, web-based HMI for industrial machines: a drag-and-drop screen editor, Beckhoff ADS and OPC UA drivers, alarms, recipes and operator access control — served as a touch-ready panel by a single Node process.

From empty page to operator panel

Three steps, all in the browser. No runtime generator, no per-machine native app, nothing to install on the panel PC except a browser.

1

Draw

Open /edit and drag widgets onto pages: labels, buttons, toggles, gauges, grids, images, 3D STL models, charts. Save configured widgets to a library and reuse them across pages.

2

Bind

Point each widget at a PLC variable — browse live TwinCAT symbols over ADS, or address OPC UA NodeIds directly. No PLC yet? The built-in simulator feeds every screen with moving data.

3

Hand over

Operators open /monitor: touch-ready, multi-language, and gated by access groups — down to a single button. Export the whole project as one .hmiproj file and load it on the next machine.

Specifications

PLC protocols
Beckhoff TwinCAT ADS, OPC UA, built-in mock/simulator for PLC-free development
Screen editor
Drag-and-drop pages; labels, buttons, toggles, gauges, grids, images, 3D STL, charts; reusable widget library; live PLC symbol browser
Alarms
Edge-detected polling on ADS and OPC UA, composite alarm text, active-alarm view with acknowledge
Access control
Named groups with capability inheritance; per-page and per-widget gating; optional LDAP gateway
Operator runtime
Touch-friendly, multi-language (operator UI localizable; designer UI in English)
Projects
Export/import the full configuration — pages, alarms, recipes, groups, machine config — as a single .hmiproj file
Deployment
One Node process serves UI and API; Docker image and Compose files; Windows portable package (no Node install on the target PC)
Audit
Local append-only log of logins, lockouts, and operator value writes
Requirements
Node.js 20+, or just Docker; any modern browser on the panel side
License
Apache-2.0 — free for commercial use, modification, and redistribution

Secure by default

HMI Studio is built for machines that will outlive several IT policies, and documents its posture against the EU Cyber Resilience Act so you can fold it into your own product's conformity work.

No known-key tokens, ever

If the JWT secret is missing or still the shipped placeholder, the backend signs with a random ephemeral secret and warns at startup — it never uses a key an attacker could look up.

Hardened login

bcrypt password hashes, account lockout after repeated failures, per-IP rate limiting on the authentication endpoints, and a warning while the default admin password is unchanged.

A paper trail

Every login, lockout, and operator value write lands in a local append-only audit log. No telemetry leaves the machine.

CRA-ready paperwork

CycloneDX SBOM generation, a coordinated-disclosure policy, and a maintained readiness matrix against CRA Annex I — see docs/CRA-READINESS.md.

Run it in two minutes

The test bench starts HMI Studio together with a real OPC UA server, so you can exercise reads, writes, and alarms with no PLC and no hardware.

With Docker

# full stack + OPC UA test server git clone https://github.com/aiolfimatt/hmi_studio.git cd hmi_studio docker compose -f docker-compose.test-bench.yml up --build

Open http://localhost:3100 and log in with admin / admin123 — then change it.

From source

# Node.js 20+ cd backend npm install node index.js # second terminal: cd frontend npm install npm run dev

Open http://localhost:3101. First run seeds an admin user, default groups, and a mock machine — every widget shows moving data immediately.
